# 这个 Skill 是怎么改进的

研究从一套固定的点餐场景开始：工具、场景、运行环境、评分方式和时间限制都保持一致，通过修改 Markdown Skill，观察同一套使用方法在两个模型上的表现。

当时保留了三个版本：空 Skill 基线、第一批 C1，以及修订偏好判断后的 C2。原 C2 的两份 Markdown 文件完整保存在 [c2](c2/README.md)，对应那次实验使用的版本。日常使用请安装 [提交版 Skill](../skills/mcd-meal-plan-output/)。

## 开发集：每道题做三次

开发集共 16 题，每题重复 3 次，所以每个模型、每个版本都有 48 次结果。模型分别是 Kimi `kimi-for-coding` 和 MiniMax `MiniMax-M3.1-Flash-Preview`。

| 版本 | Kimi 通过数 | MiniMax 通过数 |
| --- | --- | --- |
| 空 Skill 基线 | 13/48 | 42/48 |
| C1 | 45/48 | 43/48 |
| C2 | 48/48 | 47/48 |

上表采用获准的事后分析方式。C1 和 C2 各有一次 MiniMax 超时；确认执行已停止、原程序评分有效后，采用它们已有的 0 分。原始失败状态保留，分析过程没有重新运行模型或修改原记录。原开发执行并发为 1。

这些题目和反馈参与过 Skill 修改与选择，表格反映的是开发集结果。

## 独立评估：留出十道题

选定 C2 后，由独立角色在 10 道未用于优化的题上比较它和基线。每题重复 3 次，仅使用 MiniMax，同时运行的 Trial 上限为 2，每次有效执行时限为 180 秒。

| 版本 | 通过数 | 通过率 |
| --- | --- | --- |
| 空 Skill 基线 | 25/30 | 83.33% |
| C2 | 29/30 | 96.67% |

C2 多通过 4 次，提升 13.33 个百分点。两边均无超时、执行错误或补跑。

查看留出结果前，已确定通过条件：C2 均值至少为 0.75，且不低于基线。评估结束后保留已选版本，未据此修改或重新选择。结果来自 10 道题各做 3 次；比赛综合能力和统计显著性仍需要其他证据。

## 用量与评分

累计使用 **376 个 Actor Trial**，即模型任务的执行尝试次数，包含失败和中途取消的尝试：接入检查 2 次、正式开发 288 次、取消前的恢复执行 26 次、最终独立评估 60 次。

评分由程序完成，独立 Pi 审查的用量另行记录。
