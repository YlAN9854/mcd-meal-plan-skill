# 研究版如何接上真实服务

原 C2 Skill 保存在 [research/c2](../research/c2/README.md)，用于查阅当时的实验版本。日常使用请安装 [skills/mcd-meal-plan-output](../skills/mcd-meal-plan-output/)。

真实接口适配依据官方工具说明和公开业务要求完成；原版文件保持原样，留出题的具体内容和最终失败案例未用于这些调整。

| 研究时的环境 | 接入真实服务后的做法 |
| --- | --- |
| 使用固定模拟服务 `http://mcp:8000/mcp` | 连接官方 `https://mcp.mcd.cn`，从环境变量读取 Token |
| 按指定路径和 `plan.schema.json` 写结果 | 先给用户可读方案，需要 JSON 时再使用本项目的输出格式 |
| 场景提供完整的菜单属性 | 按实际返回处理，缺失的库存、营养等信息保留为未知 |
| 组合范围较小，可以核对最低价和无解情况 | 说明已查询和比较的范围；证据不足时标记为 `incomplete` |
| 模拟服务规定了故障码和 `traceId` | 按线上响应判断错误，有服务 trace 时引用，否则使用客户端可定位的调用结果 |
| 商品与优惠规则较简单 | 查询真实套餐详情和选配要求，再核对实际优惠与整单报价 |

沿用的主要方法包括：先判断结果状态、按状态填写金额、核对整单报价、分清硬性要求与偏好、为结论关联查询依据，以及输出前检查。

命令行工具用于查询和验证连接，配餐搜索由模型按照 Skill 执行。7 项本地测试覆盖服务地址、工具允许列表、个人配置保存和响应解析；真实接口检查完成了五次业务调用并取得报价。

原研究分数对应原 C2 版本。提交版目前完成了接口检查，完整模型表现还需单独测量。
